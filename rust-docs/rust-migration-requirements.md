# bpfsnoop Rust 迁移需求文档

## 1. 项目概述

将现有的 Go 语言实现的 bpfsnoop 工具完全迁移到 Rust 语言，保持所有核心功能不变，并提升性能和内存安全性。

## 2. 核心需求

### 1. 功能兼容性要求

#### 1.1 eBPF 程序管理
- **保持现有 C 源码**：继续使用 `bpf/` 目录下的所有 C 源文件
- **自动编译嵌入**：实现类似 bpf2go 的功能，将 eBPF 程序编译并嵌入到 Rust 可执行文件中
- **运行时加载**：支持从嵌入的字节码动态创建和加载 eBPF 程序
- **多架构支持**：支持 x86_64 和 arm64 架构

#### 1.2 内核函数跟踪
- **BTF 解析**：解析内核 BTF 信息，发现可跟踪的函数
- **符号表处理**：读取 `/proc/kallsyms`，建立符号地址映射
- **函数匹配**：支持通配符和正则表达式匹配内核函数
- **跟踪类型**：支持 fentry/fexit、kprobe/kretprobe、tracepoint 等多种跟踪方式
- **参数限制检测**：自动检测内核支持的最大参数数量

#### 1.3 参数过滤系统 
- **C 表达式支持**：支持复杂的 C 语言表达式作为过滤条件
- **类型安全检查**：基于 BTF 信息验证表达式类型正确性
- **动态代码生成**：将过滤表达式编译为 eBPF 字节码
- **内存访问模式**：支持 probe_read、core_read、direct_read 等多种内存访问方式

#### 1.4 网络包过滤
- **libpcap 集成**：支持标准的 pcap 过滤表达式
- **多包类型支持**：处理 sk_buff、xdp_buff、xdp_frame 等不同包类型
- **L2/L3 过滤**：支持链路层和网络层的包过滤
- **动态注入**：将 pcap 过滤器动态注入到 eBPF 程序中

#### 1.5 输出格式化
- **参数打印**：根据 BTF 信息智能格式化函数参数
- **包信息提取**：解析和显示网络包的关键信息（地址、端口、协议等）
- **调用栈输出**：支持内核调用栈的获取和显示
- **反汇编支持**：集成 capstone 进行指令反汇编

### 2. 性能要求

#### 2.1 运行时性能
- **低延迟**：事件处理延迟不超过 Go 版本的 110%
- **高吞吐**：支持高频率的内核事件跟踪
- **内存效率**：内存使用量不超过 Go 版本的 120%
- **CPU 效率**：CPU 使用率不超过 Go 版本的 110%

#### 2.2 编译时性能
- **快速构建**：完整构建时间控制在 5 分钟以内
- **增量编译**：代码修改后的重新编译时间控制在 30 秒以内
- **并行编译**：充分利用多核 CPU 进行并行编译

### 3. 开发体验要求

#### 3.1 代码质量
- **类型安全**：充分利用 Rust 的类型系统避免运行时错误
- **内存安全**：零 unsafe 代码，或将 unsafe 代码限制在明确标记的边界内
- **错误处理**：使用 Rust 的 Result 类型进行优雅的错误处理
- **文档完整**：所有公共 API 都有完整的文档注释

#### 3.2 测试覆盖
- **单元测试**：代码覆盖率达到 80% 以上
- **集成测试**：覆盖主要使用场景
- **性能测试**：建立性能基准和回归测试
- **兼容性测试**：测试多个内核版本的兼容性

### 4. 部署要求

#### 4.1 依赖管理
- **最小依赖**：尽量减少外部依赖数量
- **静态链接**：支持生成静态链接的可执行文件
- **跨平台**：支持在不同 Linux 发行版上运行

#### 4.2 向后兼容
- **CLI 兼容**：命令行参数和输出格式与 Go 版本完全兼容
- **配置兼容**：支持现有的配置文件和环境变量
- **迁移工具**：提供从 Go 版本平滑迁移的指导

## 3. 技术架构要求

### 1. 模块化设计
```
bpfsnoop-rust/
├── Cargo.toml              # 工作空间配置
├── crates/
│   ├── bpfsnoop-core/      # 核心功能库
│   ├── bpfsnoop-btf/       # BTF 解析库
│   ├── bpfsnoop-cc/        # C 表达式编译器
│   ├── bpfsnoop-pcap/      # 包过滤库
│   ├── bpfsnoop-ebpf/      # eBPF 程序管理
│   └── bpfsnoop-cli/       # 命令行界面
├── bpf/                    # eBPF C 源码（复用现有）
├── build.rs                # 构建脚本
└── README.md
```

### 2. 关键依赖选择
- **eBPF 库**: `aya` 或 `libbpf-rs`
- **CLI 解析**: `clap`
- **异步运行时**: `tokio`
- **序列化**: `serde`
- **日志**: `tracing`
- **错误处理**: `anyhow` + `thiserror`

## 7. 风险评估

### 高风险项
1. **C 表达式编译器复杂度**：重新实现可能遇到意外的技术挑战
2. **eBPF 生态差异**：Rust eBPF 生态可能缺少某些功能
3. **性能回归**：可能无法达到预期的性能标准

### 中风险项
1. **第三方依赖稳定性**：依赖库可能存在兼容性问题
2. **内核兼容性**：不同内核版本的兼容性问题
3. **开发时间估算**：技术复杂度可能导致开发时间超预期

### 缓解措施
1. **分阶段开发**：优先实现核心功能，高级功能可以后续迭代
2. **性能监控**：持续监控性能指标，及时优化
3. **备选方案**：准备技术备选方案应对风险
